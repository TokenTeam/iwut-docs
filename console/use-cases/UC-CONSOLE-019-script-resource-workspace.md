# UC-CONSOLE-019：维护平台脚本资源与版本工作页

状态：`ACCEPTED`，2026-11-10，用户授权自行设计、接受并实现脚本管理范围。实现：`LOCAL_VERIFIED`。

## 目标与权威引用

有独立脚本维护权限的操作人在 Admin Console 创建平台脚本资源、编辑元数据、建立与保存脚本版本、提交审核；其他脚本角色仅读取其职责允许的视图。业务权威为 App [UC041](../../app-center/use-cases/UC-APP-041-manage-script-resource.md)、[UC042](../../app-center/use-cases/UC-APP-042-manage-script-version-draft.md)、[UC043](../../app-center/use-cases/UC-APP-043-submit-script-version-review.md)、[UC045](../../app-center/use-cases/UC-APP-045-query-script-management-and-reviews.md)。本 UC 不另建执行器、脚本语言、审核政策、依赖图或删除能力。

共同交互与外部依赖见[设计总案](../design-notes/2026-11-09-console-completion-design.md)。平台管理员身份不隐含脚本维护权限。

## 页面结构

建议路径 `/scripts`、`/scripts/new`、`/scripts/$resourceId/versions`、`/scripts/$resourceId/settings`、`/scripts/$resourceId/versions/new` 与 `/scripts/$resourceId/versions/$versionId`。版本新建和工作页复用内容区与状态反馈，都是全页，不以浮窗承载大量编辑。

资源列表提供名称、用途与可进入的职责分区，使用正式有界分页。资源详情保留资源身份，版本、发布与分发、资源资料互为平级；版本列表不拉取正文。没有内容读取权限的发布或运维角色仍可进入其被授权分区，不能把正文403解释为整个资源不存在。

版本列表在 API 已支持的范围展示状态并选择版本，不自行假设后端搜索/排序参数。按版本状态显示只读事实或编辑入口；应用的正式/灰度/测试三卡结构不套用到脚本版本。

## 创建、编辑与保存

1. 新资源在用户明确提交名称和用途后创建；元数据修改有独立保存与失败状态，不能连带保存脚本正文。
2. 新版本先填写版本标签和正文，明确点击创建后获得真实 ID，再进入同一工作页自动保存。创建前内容是未持久化草稿，不后台生成空资源/空版本。
3. 已存在 DRAFT 以当前详情 revision 为保存基线；停止输入后串行提交完整草稿。保存期间的新输入在当前请求结束且获得有效新基线后再提交，不发送平行替换或覆盖冲突。
4. 标签创建后不可编辑。受审内容约束直接引用 UC042；首期仅 json 标识，不把客户端 JSON 解析结果作为能否保存的新增门禁，也不运行正文。清晰显示 UTF-8 字节上限与超限位置/提示。
5. 初次读取保留原始文本值；未修改时不重写正文。BOM、CRLF、空白与键顺序不能被格式化器或编辑器悄悄改变。若编辑器输入机制会转换换行，必须先明确告知并取得本次转换意图，不能把“打开页面”变成内容修改。
6. “清空正文”只修改当前工作内容；进入待保存状态且可在发送前撤回。“还原到已保存内容”取消尚未发送的自动保存，丢弃本地修改，恢复最新一次成功读回/确认保存的基线。若保存正在进行或结果未知，先停止后续写入并读回，不能声称撤回已经发送的保存。清空产生非法正文时只提示，不能自动发送非法草稿。
7. 修改未保存、冲突或结果待核实期间不送审。离页有未持久化修改时提示；不靠浏览器卸载请求兜底保存，不把正文放到本地持久存储。

保存失败保留当前会话内的编辑内容并停止自动重放；用户明确恢复后才继续。revision 冲突显示服务器已变化，允许重新读取与比较本地内容，覆盖须基于新事实由用户明确决定。写入超时先核对服务端状态；新建响应丢失不靠换标签/自动再创建规避唯一性，回到资源版本列表核对后再人工处理。

## 送审与终态

送审前确保所有待保存内容有明确结果并重读详情，显示本次资源、版本标签和提交摘要；单次明确确认调用正式 Submit。审核绑定策略、正文摘要、贡献者和资源快照以服务端回执/详情为准，界面不自填这些事实。

SUBMITTED、APPROVED、REJECTED 内容只读，显示当前审核及导航；送审后不能继续自动保存。拒绝后可复制可读正文去新建页，但需要新标签与新版本 ID，由用户明确创建，不改写或复活旧版本。不提供删除、撤回审核或直接批准入口。批准后进入[独立发布](UC-CONSOLE-021-script-publication-and-distribution.md)，不宣称自动可运行。

## 接口与依赖

使用正式 ScriptResourceService、ScriptVersionService 与 ScriptQueryService 的资源/版本查询、创建、元数据替换、草稿替换及送审。HTTP 方法、body annotation 与 ProtoJSON 按实际生成契约实现，不手写平行 DTO；int64 revision 不经 JS number。

后端已有业务契约；本人权限发现使用已接受交付的 Auth UC038 与 Gateway 增量，本轮在真实链验证其入口。资源详情只消费自身权限可读字段，缺失正文与空正文/读取失败不得混同。

## 验收安排

- 维护人创建资源、新建草稿、串行自动保存、还原/清空、送审、拒绝后建立新版本；读回文本、字节摘要和版本关系一致。
- 多标签页冲突、保存中继续输入、超时结果未知、离页/会话切换与迟到响应；旧保存不覆盖新基线或重启自动保存。
- 原文含 BOM/CRLF/非 ASCII/恰好字节上限与超限，未编辑无重写；语法无效但合约合法的文本不被前端另行禁止。
- 无维护权、只有发布/运维、独立 Reviewer 的职责披露；不从普通资源读取推断维护权。
- 真实镜像验证创建→保存→送审链；fixture 只覆盖故障/竞争，不替代真实 API 交付。
