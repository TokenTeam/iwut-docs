## 目标与权威边界

当前应用管理者在 Developer Console 回看该应用版本与公开资料的历次审核提交、批准和拒绝，查看某次历史事件，再主动进入当前资源。业务身份、事件来源、历史最小披露和聚合分页由 [App UC052 / BR-APP-067–071](../../app-center/use-cases/UC-APP-052-query-application-management-activity.md) 及[管理动态读契约](../../app-center/query-contracts/application-management-activity.md) 拥有，后端已接受并完成 UC052，实现证据见其实施记录。方向草案仅保留为设计来源，不是第二份规则权威。

[UC003](UC-CONSOLE-003-query-owned-application-versions.md) 仍读取当前 Version 及 latestReview，[UC004](UC-CONSOLE-004-query-owned-profile-revisions.md) 仍读取当前资料修订和该修订历史，本 UC 不改写它们。既有审核命令仍由 UC006/007、编辑与送审仍由 UC008/010 负责。

本用例只覆盖一个 Application 的六类审核事件，不包含编辑日志、转让时间线、平台脚本活动、跨应用/全平台聚合、个人收件、已读/未读、红点、投递、推送或应用发送消息。待接收转让及参与者详情保留 UC014，Admin 脚本历史保留 UC019–021 的独立职责。

## 页面与导航

在选中应用后的平级主导航增加“管理动态”，与概览、版本与发布、公开资料、应用设置同级。使用既有应用切换侧栏，不另建全局收件入口。

| 路径 | 责任 |
| --- | --- |
| `/applications/$applicationId/activity` | 当前应用动态列表、类型筛选、明确翻页与刷新 |
| `/applications/$applicationId/activity/$activityId` | 单项历史详情、返回列表、打开当前资源 |

两页都可直接访问。activityId 作为后端不透明定位原样使用，独立编码 path segment；不从时间、版本标签或路由参数自行构造。详情是只读整页，可从列表进入或直接分享定位，不用多层浮窗。

当前应用不在侧栏已加载页时仍按正式读取判断，不无限翻页寻找。Developer 资格下降、应用归档/暂停或 CLOSING/CLOSED 后，原权威允许的管理历史仍须可达；不沿用创建/编辑所需的 APPROVED Developer 门禁。历史页不要求 Reviewer、平台管理员或脚本 grant。

## 列表流程

1. 当前 Session 与应用上下文就绪后请求第一页，默认展示全部六类。三项筛选为“全部 / 版本审核 / 资料审核”，分别映射全部、Version 三类、Profile 三类 kinds，不添加后端未提供的状态/时间/自由搜索。
2. 每项显示“何种资源的哪次审核发生了什么”、实际发生时间、版本提交时标签或资料稳定修订序号、attempt，以及查看记录的入口。提交记录只表示当时提交，不宣称当前仍待审；批准记录不宣称已经发布或仍为当前公开资料。
3. 保留服务端顺序。相同时间不同资源、同 Review 的提交与决定都是独立项，不按时间/标签去重或在浏览器二次排序。列表不含拒绝理由，不为列表逐项请求理由。
4. 每页20项，明确提供下一页及刷新；需要上一页时使用本会话内的合法分页链。筛选变化或刷新从第一页重建，不混合不同条件页，也不后台轮询、自动扫描或估算总数。
5. V1 聚合直接合并有界来源，不使用权限后过滤的平台扫描，因此空结果没有下一 token。空 items 却带下一 token 是协议不一致，显示读取失败，不沿用其他目录“空页继续扫描”的策略。无下一 token 表示本次分页结束。
6. 每页保留自己的 asOf；事件时间与读取时间分开。跨页不是冻结快照，新提交/决定可能落在已翻过的较新区间，用户明确刷新第一页才能发现。页面不暗示已读、已送达或实时同步。

无审核活动、当前筛选无记录、读取失败与无权访问分别表达。页大小/预算、token 长度和规范 kinds 按后端正式契约消费，不额外扫描来补足一页。

## 历史详情与当前资源

单项读取成功后验证 applicationId、activityId、kind 与资源引用的一致性，展示该次固定提交或决定及实际时间。Version 标签来自原提交快照，Profile 序号来自稳定修订身份；不以当前名称或最新审核摘要覆盖旧记录。

拒绝事件详情展示该次原始非空 rejectionReason，纯文本保留原值；提交和批准事件的该字段为明确 null。不把缺字段、空拒绝理由或错误类型静默补为“无理由”。这是新 owner 历史最小披露，需随 App UC052 审核，不误称 UC034 已有完整能力。

可提供“打开当前版本”或“打开对应资料修订”，按正式 target 跳至现有详情，再重新读取当前资源。当前 Version 可能已恢复或再次送审，其内容不是旧事件的受审 snapshot。历史详情不展示 Reviewer 身份、政策正文、检查项、完整受审内容、OAuth 配置或凭据，也不借 Reviewer API 补查。

本页不承载接受、拒绝、批准、恢复、编辑或重提命令。后续操作必须进入原页面，重新取得当前事实、权限及命令基线；动态 ID、过去状态与 asOf 都不是操作凭据。

## 前端规则

<a id="br-cmg-011"></a>
### BR-CMG-011：历史事件和当前资源分开消费

列表与历史详情只消费 App 活动查询的最小投影，不通过逐个 Version/Profile 或 Reviewer 查询拼历史。列表缺少理由是正常披露边界，不能为补齐列表自动加载全部详情。打开当前资源必须明确说明导航目标并重读，不用最新资源内容替换已选历史事件。

<a id="br-cmg-012"></a>
### BR-CMG-012：活动分页和深链接有独立上下文

分页键绑定当前 Session/应用/规范筛选/读取代际与 token，详情另绑定 activityId。token 只在私有内存，不解析、修改或持久化；转让后再获同一应用管理权也不能重用旧 ownership 上下文。非法/过期 token 允许用户从第一页重新读取，不自动重试原链。

列表返回恢复仍合法的筛选、分页与阅读位置；新窗口详情先正式读取，不要求已加载列表。离开动态模块再进入时核对当前会话和应用重新读取；不能把无限期保留的私有缓存当成资格。只有当前捕获的 Query/attempt 可以消费其成功或错误，旧成功、404、403 或读回均不能更新新身份/应用/替换 Query。

<a id="br-cmg-013"></a>
### BR-CMG-013：只读失败隔离与原文保护

共享私有读取遵循 UC002 的 BR-CMG-002–004。账号身份失效沿既有 Session 恢复；统一404表达不存在或当前不可访问，不暴露目标是否存在，也不一律解释为整个应用失权。单条404只清该详情；应用列表的归属拒绝才使该应用动态范围退场，不关闭独立账号、转让或其他应用。非 Session 的403关闭对应被拒绝读取，不触发全局登出。

400 非法输入/token、500 数据损坏、503 存储不可用及网络失败不合成为空列表。坏项不丢弃后凑一页，畸形成功响应失败关闭。512 KiB 等预算错误不得通过裁剪理由、遗漏事件或改用未授权接口降级；可重新读取但不产生业务写入。

内容与理由只在当前私有内存，文本呈现、不执行 HTML/Markdown，不进入 URL、持久化存储、通用日志/遥测或测试附件。成功和错误均验证 private/no-store。切换/退场停止旧响应消费，不借读取新增标读、访问审计、通知或其他写命令。

## 验收安排

1. 六类事件与三筛选；同一 Review 的两个阶段、同毫秒顺序、跨页和不丢未返回项，空数组无 token 与畸形空页的分型。
2. Version 旧拒绝→恢复→新提交后旧 attempt 可读；Profile 不同修订；自动/级联实际拒绝复用原事件；旧批准不等于当前公开或发布。
3. 列表无理由；历史详情仅拒绝为原非空理由，其他为 null；无 Reviewer/正文/凭据泄漏，当前资源跳转重新读取。
4. 当前 owner、新旧管理权、转出再转回的旧 token、无 owner 的 Reviewer/平台管理员/运维者；资格下降及关闭后合法历史深链接。
5. 筛选/应用/Session 切换、离页、同 key 替换 Query、迟到成功/拒绝；单条404和应用归属拒绝的清理范围不同，故障不冒充空结果。
6. 键盘访问、明确事件链接/当前资源链接、列表返回焦点与阅读位置、加载/空态/错误播报，不以颜色独自表达事件类别或失败。
