# UC-CONSOLE-022：选择与审核应用脚本依赖

状态：`ACCEPTED`，2026-11-10，用户授权自行设计、接受并实现脚本管理范围。实现：`LOCAL_VERIFIED`。扩展 UC003/006/008，本轮同步受影响的既有 UC 增量，具体覆盖按实施证据记录。

## 目标与权威引用

Developer 在现有应用版本工作页选择精确脚本依赖；App Reviewer 在原应用审核详情了解这些依赖、读取获授权的固定正文并处理批准阻塞。业务权威为 App [UC048](../../app-center/use-cases/UC-APP-048-manage-application-script-dependencies.md)、[UC047](../../app-center/use-cases/UC-APP-047-resolve-application-script-content.md)、[UC049](../../app-center/use-cases/UC-APP-049-cascade-script-rejection.md)。共同交互见[总案](../design-notes/2026-11-09-console-completion-design.md)。

本用例不要求 Developer/App Reviewer 取得平台脚本五权限；各受限读取沿应用自身授权，不被 AUTH-D1 阻塞。独立决定脚本则另按 UC020。它不扩展为爬虫任务编排或脚本内容编辑器。

## Developer 版本工作页

在 [UC008](UC-CONSOLE-008-version-workspace.md) 全页加入“脚本依赖”分区，与已有版本内容共同保存、共同送审，不新建一套版本流程，也不改成大浮窗编辑。

1. 用当前 Application 上下文的 ListApplicationScriptCandidates 分页选取，展示资源名称/用途、版本标签、审核状态，以及解释选择所需的格式和摘要。只读取该 API 允许的最小信息，不能借候选列表加载未获批原文或 Reviewer 原因。
2. 添加/替换只选择 UC048 允许的精确版本；不提供“自动跟随最新/推荐版本”。每资源单项及数量上限引用后端规则，在 UI 给出明确冲突与剩余容量，不静默去重或自动删除已有项。
3. 既有引用后续失效时仍留在草稿中，显示需修正及后端允许披露的状态，提供替换/移除；不能把它伪装成当前可选候选，也不泄露私有拒绝原因。
4. 新建与替换的完整草稿显式包含 scriptReferences，空列表也明确提交。保留其他字段、未改动引用与正式排序，不因“未打开此分区”清空依赖。采用现有保存和 OCC，不能对旧服务端引用快照打局部补丁绕过校验。
5. 送审前展示固定版本引用，提交后以正式 Review snapshot 为准。被拒绝应用恢复草稿时保留引用供调整；新送审产生新快照，不继承旧决定。

## Developer 只读版本与发布提示

在 [UC003](UC-CONSOLE-003-query-owned-application-versions.md) 的详情/历史显示固定引用与正式依赖状态，区分“等待脚本审核”“引用需修正”“应用已批准但脚本未发布/被暂停”等后端实际事实。脚本已获批可以允许应用审核继续，但未发布/暂停可能仍阻止实际应用发布；不把两者合成一个“就绪”。

具体阻塞/needsReplacement 由后端读模型与错误给出，不仅凭本地脚本状态推算。资源推荐版本变动不改变旧应用引用。现有应用发布卡片继续只发布用户选择的应用版本，不附带发布脚本、替换引用或自动重试。

## Admin 应用版本审核

扩展 [UC006](UC-CONSOLE-006-review-application-versions.md) 同一详情：列出提交冻结的脚本引用、摘要/关联审核以及当前批准阻塞。审核员可选择一项，按该 AppReview 专属 GetApplicationReviewScript 读取固定原文、完整脚本政策和决定状态；每次只加载所需正文，不预取所有依赖。

正文放在可直达/返回的阅读工作区，保留应用审核上下文。只有 App 审核权的用户也能使用该受限读取；不能跳成必须有脚本全局权限的资源查询。若已有脚本审核权，可另导航到正式脚本审核详情；浏览依赖本身不意味着能够决定脚本。

依赖待审/拒绝使批准受阻时保留已获取的应用审核事实，说明需等待或修正；人工拒绝按原权限与原因规则处理，不被前端泛化的“依赖未就绪”一并禁用。决定前仍重读同次应用详情，原策略/Scope/利益冲突检查继续有效；不在前端增加伪 mandatory checkId。级联已形成应用终态时清除旧决定确认，呈现正式决定来源，不让手工批准覆盖。

## 验收安排

- 无引用、单项、满额、同资源重复、分页候选与精确版本替换；未打开分区保存不丢引用，空集合显式提交。
- SUBMITTED 脚本和应用同时待审：应用批准先受阻，脚本获批后同一应用审核可继续；应用获批但脚本未发布时实际发布仍被阻止。
- 脚本拒绝→应用级联终态→恢复草稿→换引用再送审，旧快照不变；两种提交/拒绝竞争由真实后端验收。
- Developer 不能读未获批正文；App Reviewer 只能读其 AppReview 的固定脚本且不能越权决定；独立脚本权限失效不误清 App Reviewer 专属读取。
- 真实链覆盖选择→保存→送审→依赖审核→应用审核→发布门禁，包含 Cookie/Gateway、正式 API 与镜像身份，不用 fixture 串起全部流程后宣称已接通。
