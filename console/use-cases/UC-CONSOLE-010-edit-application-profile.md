# UC-CONSOLE-010：创建、编辑与提交应用公开资料

状态：`ACCEPTED`，2026-10-30。依据用户持续 goal 的自主设计与接受授权登记；本次不改变 App 的资料或审核规则。

## 用户目标与权威边界

当前应用管理员在独立整页中创建公开资料草稿，持续编辑并保存，核对已保存内容后明确提交审核。名称、简介、图标字符串及单工作修订等语义引用 App [UC013](../../app-center/use-cases/UC-APP-013-create-application-profile-revision.md)、[UC014](../../app-center/use-cases/UC-APP-014-update-draft-application-profile-revision.md)、[UC015](../../app-center/use-cases/UC-APP-015-submit-application-profile-revision-review.md)；管理读取引用 [UC039](../../app-center/use-cases/UC-APP-039-query-owned-application-profile-revisions.md)。

技术名称与公开名称分别表达。资料获批与运行版本发布分别表达；本页不代替 Reviewer 决定，也不重定义公开指针或发布资格。

## 页面职责

- 资料修订列表保留当前公开、工作修订、历史与状态筛选，并提供新建入口。
- `/applications/:applicationId/profile-revisions/new` 是整页新建表单；`…/:profileRevisionId` 对 DRAFT 复用同一编辑结构。大量编辑不使用浮窗。
- 内容仅包括公开名称、纯文本简介、图标字符串。图标暂为不透明字符串，不加载外链图片、不执行 URI，也不提供未经后端支持的上传能力。
- 已提交、通过、拒绝的原修订保持只读；审核历史继续独立分页。拒绝详情提供“基于此资料新建修订”，进入同一个整页新建表单，预填公开名称、简介与图标字符串。旧 REJECTED 对象、审核内容和历史不变，不提供伪造的恢复命令。

## 拒绝后的新修订

2026-10-30 接受本次增量：用户从已读取且当前仍可消费的 REJECTED 详情明确选择复用内容。此操作只在当前 Session、当前应用的短命内存中交接原始表单文本，不立即创建，不加载图标内容，不把原文、审核理由或其他大字段放入 URL、浏览器 history state、Query 缓存或持久存储。

预填抵达新建页后由该页工作副本独立持有，并在该页 commit 后精确清除交接暂存；React StrictMode 初始化和 effect 重放不提前破坏它。来源退出且不是本次目标导航、导航失败或 Session/应用不符时丢弃尚未领取的暂存；旧来源 cleanup 不清除后来的新交接。直接打开、刷新或再次直接访问新建页仍为空白。新建页提示内容来自被拒绝修订、尚未创建；用户可以修改或明确清空。

导航 state 仅允许一个纯随机的一次性关联 token，不含正文、账号、应用或来源 ID，也不是可恢复正文或授权操作的凭据。目标同时匹配 token、当前 Session 与应用后才能领取内存副本；已消费 token 的 reload/back/re-enter 不能恢复正文。当前 Router 在导航被 blocker 取消后可能不 resolve navigate Promise，因此不能只依赖 finally 清理；仅在允许后的真实导航事件暂存正文，取消不产生副本，来源退场清除未触发的监听，不使用 timeout 猜测导航是否完成。

新建必须继续走已有 CreateApplicationProfileRevision，并由用户明确点击创建。不会对旧修订发送 Update、Submit 或 Restore，也不复用旧资源 ID/revision 为新资源基线。若已有 DRAFT/SUBMITTED 占据工作位，按服务端正式 409/现有读回处理，保留列表核对入口，不自动覆盖、删除或重创已有工作修订。未知创建不自动重放；已知新 ID 时只重读该资源。

## 创建、保存与送审

新建填写只存在当前页面内存，完整有效后由用户明确创建一次；创建成功取得真实 ID 后读取详情，再进入资源页。未知创建不自动重试，提供返回修订列表核对的入口；保留真实创建 ID 时仅重试读取，不重复创建。

已有 DRAFT 的有效完整快照防抖、串行保存。nullable 字段显式提交字符串或 null，不用省略字段冒充保留。If-Match 使用已读修订，不让用户填写。迟到保存响应只更新对应保存基线，不覆盖后续输入。新建“清空”只清页面；已有“还原本次打开内容”须确认可能写回服务端，并走相同并发控制。

提交审核是独立明确动作，要求当前内容有效、已保存、无在途/冲突/未知结果，并由用户确认。命令携带已读 revision。成功回执后读取真实详情和审核状态；不把提交回执当作完整管理快照，也不把 SUBMITTED 说成已公开。

## 失败、恢复与隐私

- 定义未保存、保存中、已保存、送审中、已提交、冲突/拒绝与结果未知。网络/5xx/畸形成功后的未知写不自动重放；确认失败保留可理解原因。
- 冲突或未知时暂停写入，只允许明确读取当前资料。读回展示当前状态；用户确认使用它后重新建立基线。读到目标已满足不证明原命令成功，不自行重复提交。
- 未保存、在途或未知结果离页提示；换会话、失去访问权时安全退场优先，不让提示保留旧私有表单。请求和响应消费绑定原 Session、当前应用和页面生命周期。
- 表单、审核原文和响应仅存在内存；不进 localStorage、日志或 URL。正文保持纯文本。正常交互不铺陈 revision 等技术字段，只在冲突/失败时给出必要提示。
