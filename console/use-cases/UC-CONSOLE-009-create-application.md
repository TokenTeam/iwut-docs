# UC-CONSOLE-009：创建应用

状态：`ACCEPTED`，2026-10-30。依据用户持续 goal 对前端功能设计、自行接受与实施的授权接受本有界用例。

## 用户目标与边界

开发者从我的应用列表或持续应用侧栏进入独立整页，创建一个应用并进入它的管理概览。该流程只收集技术名称，不同时创建版本、公开资料、发布配置或 OAuth 客户端。

后端业务规则引用 App [UC001](../../app-center/use-cases/UC-APP-001-create-application.md)，管理查询引用 Console [UC002](UC-CONSOLE-002-query-owned-applications.md)。名称校验、开发者资格、配额、唯一性与所有权由 App/Auth 权威执行；前端不根据列表长度推断剩余配额或资格。

## 结构与交互

- 我的应用提供明确“创建应用”入口；侧栏另有持续入口。创建位于 `/applications/new`，不伪装成一个已有 Application，不展示应用内配置选项卡。
- 表单只填写技术名称，说明创建后不可修改以及公开名称归公开资料独立管理。不 trim、改大小写或替用户生成名称，不允许传入管理员、ID 或审计字段。
- 名称的即时格式提示仅辅助填写，服务端拒绝保持权威。用户明确提交后只发送一次创建请求，在途禁用重复提交。
- 成功回执必须符合固定官方类型，返回 UUIDv7、原始技术名称、当前会话用户的管理员身份及创建时间。仅凭合法回执导航到该 ID 的概览；概览再执行正式 `GetMyApplication`，不把创建回执合成管理快照。
- 成功后让当前会话已有的应用列表和侧栏重新读取，不在前端编造计数或手工插入假的列表项。

## 错误、恢复与离页

- 明确的业务拒绝展示稳定、可理解的信息，不展示任意后端错误原文。名称占用、配额或资格失败不自动重试；用户可依据拒绝修改或退出。
- 网络失败、5xx、无法识别的成功回执或成功响应丢失属于结果待核对。停止再次创建，保留当前输入并提供“前往我的应用核对”入口；不通过相同名称或客户端筛选断言原命令已经成功，也不自动重新提交。
- 表单仅在当前页面内存保存；未提交、在途或待核对时离页提示，不在卸载时补发。成功导航不再触发未保存提示。
- 命令与回执受当前 Session 代际、页面生命周期和私有消费边界约束。换身份、Session 拒绝或私有访问被拒绝时立即退场，不能用离页确认拦截安全恢复；迟到响应不得导航或修改另一代缓存。
- 不通过普通 API Host、浏览器 Session header、数据库或临时通配 BFF 绕过缺失 surface。
