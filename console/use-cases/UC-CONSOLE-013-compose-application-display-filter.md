# UC-CONSOLE-013：编排应用展示规则

状态：`ACCEPTED`，2026-10-30，依据用户持续 goal 的自主设计、接受和实施授权登记。

## 用户目标与边界

管理员在“展示规则”整页读取当前完整规则，编排条件及条件组，明确发布或清空规则。业务语义引用 App [UC022](../../app-center/use-cases/UC-APP-022-manage-application-filter.md) 与 [application-filter-v1](../../platform/contracts/application-filter-v1.md)，不复制求值器或把 Filter 当服务端授权。

Filter 属于整个应用，作用于正式/灰度候选的客户端展示；不影响测试参与、OAuth授权或应用运行资格。没有规则不代表应用可公开访问。设置与清空即时生效，不经过审核；本地尚未发布的填写不是后端草稿。

## 结构与编排

- 沿用 `/applications/:applicationId/display-rules`。当前完整规则与本地工作树同页组织，不钻入版本/渠道或使用大编辑浮窗。
- 条件组提供“全部满足”“任一满足”“不满足”，保留有序子项；条件包含字段键、操作和值类型。增加、删除、改变组结构均只改当前内存，直到用户明确发布。
- 已有单条件或条件组可保留整棵树并包为新的“全部满足”“任一满足”或“不满足”组；仅有一个子项的外层组可移除。结构调整仍受总节点与深度限制，不需要先清空已经生效的规则。“重新编排”经确认仅清空本页填写，生效规则保持到下一次明确命令。
- 字段说明来自 Auth 正式 `GetProfileEditingSchema`，只读取目录、不读用户资料；其中本协议不能表示的 STRING_SET/ACADEMIC_GRADE 等类型不伪装为标量条件。目录缺失/失败不发明字段，也不抹掉既有规则。
- 可使用明确的自定义字段键并选择协议支持的标量类型，提示“不代表字段当前已发布或用户已经提供”。客户端按后端结构约束辅助检查；服务端仍校验完整规则，不能把本地预检当授权或实际用户命中证明。
- 字符串不 trim、转数字、归一化或执行；日期与整数用各自输入。EXISTS/NOT_EXISTS 不发送值。保留当前树与原始操作顺序，不用扁平表单丢失 NOT/嵌套含义。
- 不加载任意 URI，不请求真实用户资料或回传命中结果；不显示无后端依据的覆盖人数和预览命中率。

## 保存、清空与恢复

完整规则读取使用独立专用 API，不从应用管理摘要构造规则树。首次 ALLOW_ALL/revision 0 是正式返回的逻辑状态；正常页面不展示 revision 让用户填写。

发布规则与清空为独立明确确认操作，均绑定已读取的 Filter 前置值。设置发送完整树；清空依后端 DELETE query 契约，不套版本 If-Match，也不把清空解释为删除历史。相同内容的 no-op 如实表达。

成功回执后读取当前完整规则；读取结果须不早于已确认回执。不会把命令 resource 伪造成管理查询时间。网络、5xx、畸形成功、冲突或拒绝后暂停写入，保留本地输入并提供明确读回、对照和采用；读回满足目标不证明之前的未知请求一定成功，不自动重放任何写。

“还原本次打开内容”只重置尚未发布的工作树；已发布变更不会因此回滚服务端，需要新一次明确发布。离页时提示未提交/在途/未知结果；不通过卸载保存，不把私有规则写入本地持久存储。

## 私有读取与验收

沿用当前 Session/应用/lifetime 的私有消费守卫和精确 Query 实例保护。失权或会话变化优先清空工作树与读回内容；迟到响应不能恢复旧私有配置。健康读取失败可以保留同上下文已确认快照并标注暂时不可确认，但不能据此偷偷更新命令前置值。

固定 API `6fea3db` 生成 Filter 和字段目录类型；Gateway `9d6a27f` 已开放对应 Developer 普通路由，后端不是新增依赖。UI、类型/合成验证、真实镜像设置/清空及只读回归分别记录。

验收覆盖：嵌套与NOT、四种标量和无值操作、空/未知目录、最大节点/深度、完整规则原样读回、revision0、no-op、发布/清空确认、冲突未知不重放、重置/离页与新Session/Query实例保护。不能用组件fixture替代真实发布或应用公开展示端的求值交付。
