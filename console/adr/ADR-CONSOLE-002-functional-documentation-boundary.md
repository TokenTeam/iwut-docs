# ADR-CONSOLE-002：前端功能文档与视觉设计边界

状态：`ACCEPTED`

日期：2026-10-05

## 背景

Console 采用与后端相似的文档先行流程，但前端同时包含功能语义和视觉表达。如果把具体配色、尺寸或组件外观写入权威 UC/BR，日常视觉迭代会制造无意义的设计漂移；如果完全不记录客户端行为，又会使登录恢复、冲突处理、敏感信息和错误状态只能从组件代码推断。

## 决定

Console 权威文档只固定功能与可验证的交互语义，不固定具体视觉样式。

一个前端 UC 按需要描述：

- actor、用户目标、入口条件、成功出口与中断恢复；
- 依赖的后端 UC、查询契约、Gateway 路由和稳定错误 reason；
- 页面或流程必须表达的业务状态、可执行动作及禁止动作；
- loading、empty、partial、error、permission denied、conflict 和 result unknown 等功能状态；
- 导航、刷新、返回、重复提交、重试和并发冲突语义；
- Session、设备私钥、一次性 secret 和个人数据的客户端边界；
- 键盘操作、焦点、语义标签、错误关联等功能性可访问性验收；
- 能由组件测试、契约测试或 E2E 自动验证的验收场景。

下列内容不进入 UC/BR 的权威要求：

- 品牌色、字体、字号体系和插画风格；
- 固定像素间距、圆角、阴影与装饰效果；
- 不影响功能结果的布局偏好和动画表现；
- shadcn/Radix 组件的内部组合细节和 CSS class 清单；
- 截图本身所偶然体现、但未被功能文本声明的行为。

视觉原型、设计稿和实现截图可以作为非权威协作材料。若某项表现影响可用性、安全、隐私或可访问性，应把其功能结果写入 UC/BR，而不是把某个像素实现提升为业务规则。

## 后端语义引用

Console UC 不复制 Auth/App/Gateway 已有 BR。需要组合后端能力时引用其稳定 ID、查询契约或平台契约，并只定义前端新增的编排和体验语义。后端契约缺失时登记依赖缺口，不在前端文档里发明临时业务事实。

## 结果

- 功能设计可以在视觉风格变化时保持稳定；
- 页面状态、失败恢复和安全边界仍能在编码前评审并自动验收；
- 组件库与 CSS 可以迭代，不需要为纯视觉调整修改 UC；
- 视觉一致性需要由实现层主题、组件预览和视觉回归测试维护，而不是由业务规则维护。
